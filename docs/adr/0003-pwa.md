# 0003. PWA вместо нативного приложения

Статус: принято (фаза 0, офлайн и установка — фаза 11).

## Контекст

Пользователи: студенты с телефонами на Android и iOS, кухня и касса на планшетах, заведующая
и админ на ноутбуках. Команда небольшая, срок — один учебный год. Публикация в App Store и
Google Play требует аккаунтов разработчика, ревью и отдельной сборки на каждое обновление.

## Решение

Одно веб-приложение на React + TypeScript, оформленное как PWA:
- `manifest.webmanifest` и иконки: приложение ставится на главный экран;
- service worker `sw.js`: оболочка приложения и последнее меню доступны без сети;
- Web Push для уведомлений «Готов, полка N», плюс Telegram-бот и уведомления в приложении;
- QR на выдаче сканируется камерой из браузера.

## Последствия

- Один код для всех ролей и устройств, обновление — обычный деплой, без магазинов.
- Студенту не нужно ничего устанавливать: достаточно ссылки или QR-кода у кассы.
- На iOS Web Push работает только у приложения, добавленного на экран «Домой» (iOS 16.4+).
  Поэтому есть Telegram и уведомления внутри приложения.
- Нет доступа к нативным API, но они и не нужны: камера и уведомления есть в браузере.
- Без сети заказать нельзя: оплата и бронирование слота требуют сервера, в интерфейсе это
  показано баннером.
