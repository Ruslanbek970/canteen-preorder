# 0001. Backend на FastAPI

Статус: принято (фаза 0).

## Контекст

Нужен REST API с WebSocket для кухни и статусов заказа, строгая валидация входных данных,
документация API для защиты и для фронтенда. Команда знает Python, а прогноз спроса
(scikit-learn) тоже на Python. Нагрузка небольшая: одна столовая, сотни заказов в перемену.

Варианты: Django + DRF, Flask, FastAPI, Node.js (NestJS).

## Решение

FastAPI + Pydantic v2 + SQLAlchemy 2.0 (синхронный, psycopg 3) + Alembic.

- Схемы Pydantic дают валидацию и OpenAPI: Swagger на `/api/docs` получается сам, а таблица
  эндпоинтов в `docs/api.md` генерируется из него.
- Зависимости (`Depends`) удобны для `require_roles(...)` и сессии БД на запрос.
- WebSocket есть из коробки.
- Один язык с ML-частью: worker и прогноз используют те же модели и сервисы.
- Синхронный SQLAlchemy проще для атомарных `UPDATE ... RETURNING` и транзакций, чем async.
  Синхронные эндпоинты FastAPI выполняет в пуле потоков, его размер равен пулу соединений
  с базой (`docs/load-test.md`).

## Последствия

- Django admin нет: админка написана на React, это часть диплома.
- Структура (роутеры → сервисы → модели) не навязана фреймворком, её держим сами
  (`CLAUDE.md`).
- Под нагрузкой 500 студентов p95 = 138 мс на одной машине, этого хватает с запасом.
