# Сценарий показа на защите (5–7 минут)

По SPEC 17. Все аккаунты с паролем `demo1234`, данные из `make seed`.

## Подготовка (до защиты)

1. Сервер или ноутбук: `make dev` (или продакшен из `docs/deployment.md`), `make seed`, если
   база пустая. Для показа Grafana: `make monitoring`.
2. Три окна или устройства:
   - телефон или окно шириной 390 px: `student@demo.kz` (аллергия: орехи — тяжёлая, молоко —
     лёгкая), группа SE-2301 с расписанием пар;
   - планшет или второе окно: `cook@demo.kz` → «Кухня»;
   - третье окно: `cashier@demo.kz` → «Выдача»;
   - ноутбук: `manager@demo.kz`, вкладка Grafana `http://localhost:3000` (`admin` / `admin`).
3. Показ лучше делать в учебный день, когда у демо-группы есть перемены впереди. Если пары уже
   закончились, выбрать «Завтра» в меню (открывается после 15:00) или войти как
   `teacher@demo.kz`: преподавателю доступны все слоты.
4. Терминал для нагрузки: `docker compose exec backend python -m scripts.load_setup` за
   минуту до шага 7 (токены живут 15 минут).
5. Язык интерфейса — русский (переключатель вверху справа), на шаге 2 можно на секунду
   показать казахский.

## Показ

**1. Проблема (слайд, 30 с).** Очередь в перемену 15–20 минут, обед не успевают съесть;
столовая не знает, сколько готовить, остатки выбрасывают.

**2. Телефон студента: меню (1 мин).**
- «Меню», «Главная столовая». У каждого блюда цена, остаток порций, КБЖУ, отзывы.
- «Медовик» (грецкий орех) помечен красным «Опасно для вас», кнопки заказа нет. Блюдо с молоком
  можно заказать только с подтверждением. Проверка идёт только по ингредиентам, без ИИ, и
  данные об аллергии видит только сам студент.
- Фильтр «Без моих аллергенов».
- В корзине «Время выдачи»: показаны только слоты в перемены группы SE-2301, у тихого слота
  может быть скидка.

**3. Оплата (30 с).** «Заказать» → учебная страница оплаты → «Оплатить». На экране QR-код,
номер `A-0NN` и статус «Оплачен».

**4. Планшет кухни (1 мин).**
- Заказ появился на доске сам, без обновления страницы, в группе своего слота.
- Сверху «Собрать к ближайшим слотам»: сколько каких блюд нужно.
- «Весь слот в работу» → «Наклейка» → «Печать».
- «Готово»: система назначила полку. На телефоне студента сразу «Готов, полка N».

**5. Выдача (30 с).** «Сканировать QR камерой» (или ввести номер) → заказ с составом и
полкой → «Выдать». У студента статус «Выдан».

**6. Панель заведующей (1,5 мин).**
- «Сегодня»: заказы, выручка, остатки, загрузка слотов.
- «Отчёты» → «Прогноз против факта»: две модели (`baseline_avg` и `gbm_v1`), MAE и MAPE,
  график. Выбирается модель с меньшей ошибкой на бэктесте (`docs/ml/results.md`).
- «Скидки»: предложенная скидка на остаток, который по прогнозу не продастся, → «Одобрить».
  Скидка сразу видна в меню студента.
- «Отчёты» → «Списания».

**7. Нагрузка (1 мин).** В терминале `docker compose --profile load run --rm k6`, на экране
Grafana «Столовая: обзор»: запросы в секунду, p95, заказы в минуту, заполненность слотов.
Итог из `docs/load-test.md`: 500 студентов за 5 минут, p95 = 138 мс, 0 ошибок 5xx; после
теста `python -m scripts.load_check` показывает, что ни один слот и ни одно блюдо не
перепроданы. Почему так: атомарные `UPDATE` (`docs/adr/0002-atomic-updates.md`).

**8. Пилот (30 с, если был).** Время в очереди до и после, доля списанной еды.

## Если что-то пошло не так

- Нет слотов в корзине: перемены группы уже прошли — выбрать «Завтра» или войти как
  преподаватель.
- Заказ не появился на кухне: проверить, что он оплачен, и обновить страницу (WebSocket
  переподключится сам).
- Нет предложенной скидки на остатки: worker предлагает их с 13:30 каждые 30 минут. До этого
  показать скидку на тихий слот: «Скидки» → выбрать слот → «Создать скидку».
