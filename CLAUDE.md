# CLAUDE.md

Правила работы в этом репозитории. Читай этот файл и `docs/SPEC.md` перед любой задачей.

## Проект

Веб-приложение предзаказа в университетской столовой (дипломный проект команды студентов из Казахстана). Студент заказывает обед до перемены, выбирает слот выдачи в свою перемену и забирает заказ по QR. Кухня видит заказы по слотам, система прогнозирует спрос и предлагает скидки на остатки.

- Полное ТЗ: `docs/SPEC.md`
- Эталонная схема БД: `docs/schema.sql` (в файле схема называется `canteen` для запуска в pgAdmin; в приложении используем схему `public`)
- Журнал прогресса: `docs/PROGRESS.md`

## Стек

Backend: Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.0 (sync, psycopg 3), Alembic, PostgreSQL 16, Redis, APScheduler, aiogram 3, scikit-learn.
Frontend: React + TypeScript + Vite, React Router, TanStack Query, Zustand, Tailwind, i18next (ru, kk, en).
Инфраструктура: Docker Compose, nginx, GitHub Actions, Prometheus, Grafana, k6.

## Как работать

1. Работаем строго по фазам из раздела 16 `docs/SPEC.md`. Одна фаза за раз. Не начинай следующую, пока в текущей не выполнен пункт «Готово, когда».
2. В начале фазы составь короткий план (список задач) и покажи его. Потом делай.
3. После каждой фазы: прогони линтеры и тесты, обнови `docs/PROGRESS.md` (что сделано, что отложено, известные проблемы, как проверить), сделай коммит.
4. Если в ТЗ чего-то не хватает или оно противоречит само себе, выбери самый простой разумный вариант, запиши решение в `docs/PROGRESS.md` в раздел «Решения» и продолжай. Спрашивай пользователя только если выбор необратимый или сильно меняет объём работ.
5. Не добавляй функции, которых нет в ТЗ, без вопроса.
6. Пользователь общается на русском. Отвечай на русском. Код, имена переменных, коммиты и комментарии в коде — на английском. Тексты интерфейса — только через i18n, сначала ru, потом kk и en.

## Правила кода

### Backend
- Слои: `api/routers` (HTTP, роли) → `services` (бизнес-логика, транзакции) → модели. Никакой бизнес-логики в роутерах.
- Деньги — `Decimal` и `NUMERIC(10,2)`. Никогда float.
- Время — `timestamptz` в базе, `datetime` с tzinfo в Python. «Сегодня» считается в `Asia/Almaty` (функция `app.utils.time.today_local()`), не в UTC.
- Списание порций и бронирование слота — только атомарным `UPDATE ... WHERE остаток >= :qty RETURNING` (SPEC 5.3). Без чтения-проверки-записи.
- Переходы статусов заказа — только через одну функцию сервиса с таблицей разрешённых переходов (SPEC 7.6). Перед сменой статуса `SET LOCAL app.current_user_id`.
- Схема БД меняется только миграциями Alembic. Ручной SQL в миграциях допустим для триггеров и представлений.
- Ошибки бизнес-логики — свои исключения (`DomainError` с `code` и `message`), обработчик превращает их в формат ошибки из SPEC 8.
- Проверка ролей — зависимость `require_roles(...)` на каждом эндпоинте. Сотрудник видит только свою столовую.
- Все настройки — через `app/config.py` (pydantic-settings) из env. Никаких секретов в коде.
- Для каждой новой функции сервиса — тест. Обязательные тесты перечислены в SPEC 13.
- Форматирование и линт: `ruff format`, `ruff check`.

### Frontend
- TypeScript strict. Типы ответов API в `src/api/types.ts`, запросы через TanStack Query.
- Структура по фичам: `src/features/<feature>/` (страницы, компоненты, хуки этой фичи).
- Все строки интерфейса через `t('...')`. Ключи в `src/i18n/ru.json`, `kk.json`, `en.json`.
- Mobile-first для студента (проверять на ширине 360 px), планшет для кухни и кассы.
- Цены выводить функцией `formatPrice` (`1 500 ₸`), время — `formatTime` в поясе Asia/Almaty.
- Состояние загрузки, пустое состояние и ошибка есть на каждом экране со списком.

### Git
- Ветка `main` всегда рабочая. Коммиты маленькие, сообщения в стиле Conventional Commits на английском: `feat(orders): atomic slot booking`.
- `.env` не коммитить.

## Чего не делать

- Не подключать реальные платёжные системы: только `MockPaymentProvider` (SPEC 7.7).
- Не использовать ИИ для решения, можно ли человеку блюдо при аллергии: только правила по ингредиентам (SPEC 7.3).
- Не показывать данные об аллергиях никому, кроме владельца. Кухня видит только строку «АЛЛЕРГИЯ: ...».
- Не удалять и не переписывать тесты, чтобы они прошли.
